AgentFence

Guardrails for AI coding agents on shared Linux hosts — an HPC cluster, a lab server, a jump host, anywhere several people share one machine.

What it is

AgentFence stops an AI coding agent doing damage by accident: deleting the wrong files, reading other people's home directories, cancelling other people's jobs, or taking a login node down with it.

It writes no sandbox of its own. It switches on and standardises the ones the agents already ship — Claude Code's bubblewrap sandbox, and cplt's Landlock and seccomp for everything else — then puts ordinary systemd and filesystem limits underneath them.

Covered agents: Claude Code, GitHub Copilot CLI, OpenCode, Antigravity, Pi and goose.

Install

curl -fsSLO https://github.com/SushantGautam/AgentFence/releases/latest/download/agentfence
curl -fsSLO https://github.com/SushantGautam/AgentFence/releases/latest/download/agentfence.sha256
sha256sum -c agentfence.sha256
chmod +x agentfence

sudo ./agentfence          # what would change. Changes nothing.
sudo ./agentfence apply    # make it so. Asks first.

One self-contained file. It needs bash, coreutils and python3, nothing else, and no network access at run time — which matters on cluster nodes that have none.

What it does on a node

  • Blocks an agent from reading ~/.ssh or other users' homes, writing to /etc, running sudo, or cancelling other people's Slurm jobs.
  • Caps per-user memory, CPU and PIDs on login nodes only, and only when nothing else already does that job. Compute nodes stay Slurm's.
  • Records any edit to the policy files with auditd.
  • Converges: apply covers first install, upgrade, and repairing a node someone edited by hand.

Six verbs

CommandDoes
agentfenceStatus. Exit 0 match, 1 drift, 2 error — so agentfence || alert works from cron.
agentfence applyMake the node match. Asks first.
agentfence configSettings in effect, and which layer each came from.
agentfence doctorChecks, which shims resolve, and cplt doctor.
agentfence initWrite out templates you can edit.
agentfence uninstallRemove everything it installed.

Customise without forking

Your filesystem layout and caps are settings, not source edits. Policy is layered on top of what ships, never replaced wholesale:

agentfence init --config ./site.conf --policy-dir ./policy
agentfence apply --config ./site.conf --policy-dir ./policy

<name>.append adds to a shipped file, managed-settings.overlay.json merges into the Claude Code policy, and a desired-state manifest installs files of your own. Overlays can add rules but cannot remove a shipped one by omission, and cannot switch the sandbox off — that is refused before anything is written.

How far this is tested

CI installs it on a throwaway Ubuntu runner on every push and verifies the policy that lands is valid, that a second apply is a no-op, that tampering is detected and repaired, and that uninstall leaves nothing behind.

It has not run on a real multi-user machine — no real users, no shared filesystem, no Slurm, and CI installs neither bwrap nor cplt. The convergence logic is exercised; the enforcement is not. Treat a first apply on a real node as untested: one node, watched.

Scope

AgentFence addresses an agent doing something destructive under its user's own authority. It deliberately does not defend against a user who sets out to bypass it — that user already has a shell, and the agent adds no capability they lack. Designing for that produces an unmaintainable AppArmor and exec-interception arms race.
